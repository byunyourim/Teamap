# 아키텍처 Invariant (범용)

명시적으로 바꾼다고 하지 않는 한 협상 불가한 원칙 카테고리.
planner가 계획 수립 과정에서 참조한다.

각 프로젝트의 구체 원칙은 `.claude/refs/project/architecture-invariants.md`에 적는다.
planner는 **두 파일을 모두 참조**해야 한다.

## 일반 원칙 카테고리

1. **순수 코어 원칙** — 도메인 로직 레이어(외부 IO·통신 없는 모듈)에 외부 npm 의존 추가 금지.
   외부 의존이 필요한 코드는 별도 레이어(client·adapter 등)에 둔다.

2. **의존성 방향** — 어댑터·IO 레이어는 코어를 사용하지만, 코어는 어댑터를 모른다.
   역방향 import 금지.

3. **이중 등록 지점** — 등록 배열·라우터 매핑과 핸들러 구현처럼,
   한 곳만 수정하면 동작하지 않는 지점을 명시한다 (놓치기 쉬운 단일 실패 지점).

4. **모듈 시스템 일관성** — ESM/CJS 혼용 금지, import 확장자 규칙 등 프로젝트가 정한 모듈 규칙 유지.

5. **환경변수 경계** — `process.env` 직접 접근을 어느 레이어로 제한할지 정한다.
   보통 코어·도메인 로직은 직접 읽지 않고, 어댑터·진입점에서만 읽는다.

## 추가 규칙

위 5개 카테고리에 들어가지 않지만 협상 불가한 프로젝트별 원칙은
`refs/project/architecture-invariants.md`에 별도 항목으로 추가한다.
