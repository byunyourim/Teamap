# debug-root-cause

목표: 가장 가능성 높은 원인을 증거 기반으로 찾고, 수정 방향을 제시한다.
**코드는 직접 수정하지 않는다. 분석과 보고만 한다.**

## 워크플로우

```txt
1. 에러 메시지 그대로 읽기
2. 실패 위치와 조건 추출
3. 관련 파일만 탐색
4. 원인 후보 순위화
5. 수정 방향 제안 (구체 코드 X, 방향만)
6. 검증 방법 제시
7. 사용자 보고 후 대기
```

## 규칙

- **코드를 직접 수정하지 않는다.** 수정 방향만 제시한다.
- 에러 문구를 무시하지 않는다.
- 파일/라인/명령을 먼저 본다.
- 관련 없는 리팩토링을 제안하지 않는다.
- 원인이 불확실하면 확률과 근거를 분리해서 말한다.
- 한 번에 큰 수정보다 작은 재현/검증을 우선한다.

## 분석 후 흐름

1. 분석 결과를 아래 "출력 형식"으로 사용자에게 보고하고 대기한다.
2. 사용자가 수정 진행을 명시적으로 요청하면 (예: "그렇게 고쳐줘", "수정해줘"),
   orchestrator를 호출하면서 **분석 결과 전체를 prompt에 포함**해 전달한다.
   - 메인 context의 분석을 developer가 재활용 → 파일 재탐색·재분석 토큰 절약
3. 사용자가 거부하거나 다른 방향을 제시하면 즉시 중단 또는 재분석.

## 출력 형식

```md
## 가장 가능성 높은 원인
## 근거
## 다른 가능성
## 수정 방향
## 검증 방법
## 리스크
```
