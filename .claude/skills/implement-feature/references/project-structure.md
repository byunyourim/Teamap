# 프로젝트 구조

implement-feature 스킬에서 구현 위치를 결정할 때 참조한다.

## 어디서 정보를 얻나

**프로젝트의 디렉토리 구조·핵심 모듈·수정 주의사항은 `CLAUDE.md`의 "아키텍처 개요" 섹션에 적혀 있다.**

작업 전에 다음 순서로 확인:

1. `CLAUDE.md` "아키텍처 개요" — 전체 구조 다이어그램
2. `CLAUDE.md` "아키텍처 Invariant" — 협상 불가 원칙 (의존성 방향, 코어 격리 등)
3. `CLAUDE.md` "환경변수 전파 체인" — env 읽는 위치

## 위치 결정 원칙

- **기존 패턴 재사용 우선** — 비슷한 기능이 어디에 있는지 먼저 검색
- **레이어 경계 준수** — Invariant의 의존성 방향 어기지 않기
- **이중 등록 지점 확인** — Invariant에 명시된 "두 곳 함께 수정" 지점 놓치지 않기

## CLAUDE.md에 정보가 부족하면

해당 프로젝트의 `CLAUDE.md`가 충분히 갱신되지 않은 상태. 다음 중 하나:

1. 실제 디렉토리 구조를 직접 탐색 (`ls`, `tree`, `find`)
2. `package.json` / `go.mod` / `pom.xml` 등 manifest 확인
3. 진입점 파일(`src/index.*`, `main.*` 등)부터 import 따라가기

조사 후 발견한 구조는 차단 사항이 아닌 정보로 보고하고, 사용자가 CLAUDE.md를 보강하도록 안내.
